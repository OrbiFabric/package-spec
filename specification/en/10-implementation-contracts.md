# Package 2.0 Implementation Contracts / 实施合同

Official English Translation.

## 1. Contract authority / 合同权威

`PKG-CONTRACT-001`: This chapter freezes the conceptual fields in 00–09 into exact contracts; its contracts and schemas/ replace recommended/conceptual examples on the same topics. Implementations MUST validate both JSON Schema 2020-12 structure and this chapter's relational/byte constraints. Schema `$id` values are stable identifiers, not network dependencies; repository files provide offline copies. All control JSON MUST be valid UTF-8 without BOM, duplicate keys, isolated surrogates or a trailing second JSON value. Unknown optional properties are preserved and safely ignored only where schemas allow additionalProperties; closed objects reject unknown fields and extensions use declared namespaces. Unknown fields MUST NOT change known Core semantics.

## 2. Exact tree / 精确目录

`PKG-CONTRACT-002`: Core MUST contain `.packtell/format.json`, `package.json`, `HEAD`, `versions/`, and `objects/sha256/` (the last four relative to `.packtell/`). Each committed Version directory MUST be `versions/<package_version_id>/` containing exactly `version.json` and `manifest.json`; VersionSubject is derived, not a separately stored authority file. Object paths are `objects/sha256/<first 2 digest characters>/<full 64-character digest>`; files contain raw bytes without a header. metadata/package.json, notes.json, tags.json, provenance.json and history/events.ndjson may be absent in Core (empty title, revisions/records/events respectively); Complete requires them. verification/versions/<version_id>/<signature_id>.json stores a signature; evidence/deliveries/<delivery_id>/delivery.json stores a delivery; evidence/objects/<evidence_id>.json stores evidence. extensions/<namespace>/ stores arbitrary safe regular files/directories. Other control paths MUST NOT occur; unused optional directories may be absent. Root payload names are otherwise unrestricted by business layout, but case-fold/NFC aliases of root `.packtell` are reserved; nested `.packtell` is ordinary payload. Readers MUST inspect only the caller-selected Root discriminator, not recursively guess authority from ancestors or descendants.

## 3. HEAD bytes / HEAD 字节

`PKG-CONTRACT-003`: HEAD MUST be exactly ASCII `unborn` followed by one LF (hex `756e626f726e0a`), or a lowercase UUIDv7 followed by one LF (37 bytes). BOM, CRLF, whitespace, extra lines, JSON quotes, empty files and missing LF are forbidden. With unborn HEAD, versions/ MUST be empty; committed HEAD MUST refer to an existing Version directory of the same Package. Malformed encoding is INVALID_HEAD; a well-formed reference to a missing Version is MISSING_PARENT. Ordinary payload edits MUST NOT move HEAD.

## 4. Linear history / 线性历史

`PKG-CONTRACT-004`: A Version's parent_version_id MUST always be present: JSON null for the unique root with ordinal=1; otherwise exactly one UUIDv7 with ordinal=parent.ordinal+1. ordinal MUST be an integer in 1..9007199254740991 and is not identity. The HEAD→parent chain MUST cover every directory in versions/ exactly once; cycles, multiple roots, detached versions, duplicate ordinals, cross-Package parents, parent arrays, branches/named refs/merges/DAGs are INVALID (MISSING_PARENT for absent parents, INVALID_SCHEMA for schema-shape errors, NON_LINEAR_HISTORY otherwise). Dirty state does not create a branch. Concurrent/offline writers MUST compare expected and actual HEAD before publication, returning STALE_HEAD and reconciling first on conflict; silent divergent commits are forbidden. Unaccepted proposals are not committed history and MUST NOT appear in versions/. Copy/reuse/derivation/supersession use provenance relationships; future branching requires a separate compatibility decision and may require a major upgrade.

## 5. Format and identity / 格式与身份

`PKG-CONTRACT-005`: format.v2.schema.json and package.v2.schema.json freeze the discriminator and stable creation facts. protocol=`orbifabric.package`, protocol_version=`2.0`, tree_profile=`orbifabric.package-tree.v1` MUST match exactly; an absent discriminator is NOT_PACKAGE and other protocol/version/tree values are UNSUPPORTED. profiles/required_capabilities/optional_capabilities MUST be unique and sorted by UTF-8 bytes; capability categories are disjoint. Unknown required capabilities MUST fail closed as UNKNOWN_REQUIRED_CAPABILITY; unknown optional capabilities are preserved. Unknown profiles return UNSUPPORTED and cannot claim profile conformance. Extension declaration namespaces are unique and sorted; required_capability=null means optional, otherwise the value MUST occur in required_capabilities. Extension paths and declarations correspond one-to-one; empty extension directories are permitted. Package identity/created_at are immutable throughout its lifetime.

## 6. Version fields / Version 字段

`PKG-CONTRACT-006`: package_id/package_version_id in version.v2.schema.json MUST agree with the directory and manifest; created_at is a commit fact, not trusted third-party time. Protocol/tree values follow this chapter; profiles/capabilities are frozen commit-time references and later format changes do not rewrite them; required capabilities are checked for every historical Version too. Current format required_capabilities MUST cover capabilities required by all historical Versions. sealed_metadata is an immutable Version snapshot, with a required but possibly empty title and optional description/extensions; current metadata edits do not change it. label is an optional sealed display value and MUST NOT determine identity. Empty Packages and Versions containing only empty directories are valid. Signatures, representations, Delivery and network access are not prerequisites for a Version to exist.

## 7. Manifest and identity / Manifest 与身份

`PKG-CONTRACT-007`: entries in manifest.v2.schema.json MUST describe the entire historical logical tree; the implicit Root has no FolderID/name/entry. Root children have parent_folder_id=null; other parents MUST reference folders in the same manifest. Files have only file_id and folders only folder_id; both identity fields together are forbidden; entry IDs are unique within a manifest and cannot change kind or be reused for another entity across Versions. entries MUST sort by entry UUID text in UTF-8 order (one order across files/folders). name is one NFC component; full paths derive recursively from parent+name; cycles, orphans and sibling collisions are rejected. Empty folders have explicit entries. Rename/move preserve ID; content changes preserve FileID and change ContentID; copies use new IDs. Equal ContentIDs MUST have equal sizes. Unknown optional manifest/entry fields participate in the full manifest digest without altering known semantics.

## 8. Working Tree and diff / 工作树与差异

`PKG-CONTRACT-008`: Readers MUST compare current Root payload derived paths, kinds and whole-file ContentID/size against the HEAD manifest, including empty directories and ignoring permissions/mtime/owner/inode. HEAD containing unborn means UNBORN; equality means CLEAN; additions/removals/moves/renames/content differences mean DIRTY; inability to read safely means UNREADABLE. DIRTY MUST NOT fail committed content integrity. External filesystems carry no FileID; the same path/kind may retain the HEAD ID and explicit Host identity tracking may prove rename/move; equal bytes alone cannot uniquely distinguish copy/rename, so ambiguity is Added/Removed without fabricated continuity. Diff MUST report ID-matched path and content changes separately. Newly scanned IDs and proposals belong to Host working state until committed in a manifest.

## 9. Canonical JSON bytes / Canonical JSON 字节

`PKG-CONTRACT-009`: Define J(x)=orbifabric.canonical-json.v1 on the Package 2.0 restricted domain: null/boolean/string/array/object and integers in -9007199254740991..9007199254740991. Input parsing MUST reject floats, exponents, -0, NaN/Infinity; integers are only `0` or `-?[1-9][0-9]*`. Object keys recursively sort lexically by Unicode scalar UTF-8 bytes; arrays retain order. Strings MUST escape only quote as `\"`, backslash as `\\`, U+0008/0009/000A/000C/000D as `\b/\t/\n/\f/\r`, and other U+0000..001F as lowercase `\u00xx`; all other scalars are direct UTF-8 (including /, <, >, &, U+2028/2029 and non-BMP), without arbitrary NFC text conversion. Output MUST have no BOM, whitespace or trailing LF; true/false/null are lowercase. Input JSON may contain insignificant whitespace and equivalent string escapes; digests always use J(parsed value), not original formatting. H(b)=`sha256:`+lowerhex(SHA-256(b)).

## 10. Content commitment / 内容承诺

`PKG-CONTRACT-010`: ContentID MUST be H(whole-file raw bytes), including zero-length bytes, without text decoding, newline conversion or path prefixes. Content commitment input C is an array of distinct (content_id,size) objects from the manifest, sorted by content_id; each object has exactly `content_id` and `size`; repeated references appear once and an empty manifest yields `[]`. content_commitment MUST equal H(ASCII `orbifabric.package.content-set.v1` + LF + J(C)). This is an explicit content-set commitment, not V1 Merkle leaves or hex-pair rules; Core requires no separate Merkle file. Object filenames use the full digest; verification checks bytes and size rather than trusting names.

## 11. VersionSubjectV2 / VersionSubjectV2

`PKG-CONTRACT-011`: version-subject.v2.schema.json MUST be derived field-by-field: schema/domain are schema constants; package_id/package_version_id/parent_version_id/ordinal/created_at/protocol/protocol_version/tree_profile/profiles/required_capabilities/optional_capabilities come directly from validated version.json; package_digest=H(J(package.json)); version_digest=H(J(entire version.json)); manifest_digest=H(J(entire manifest.json)); content_commitment follows the preceding clause; sealed_metadata_digest=H(J(version.sealed_metadata)). The subject digest MUST be H(ASCII `orbifabric.package.version-subject.v2` + LF + J(subject)). Root parent is null, never omitted or an array. The subject MUST NOT contain container bytes/hash, current mutable metadata, later evidence/signatures, local paths, credentials, DB IDs or online status. Full version_digest includes label and unknown optional fields, preventing unsigned authority.

## 12. Signature envelope / 签名封装

`PKG-CONTRACT-012`: version-signature.v2.schema.json defines the complete envelope E. Verifiers MUST recompute the subject digest from manifest/version, cross-check package/version/signature IDs against paths, derive fingerprint=H(raw 32-byte public key), and require canonical unpadded base64url public_key/signature decoding to 32/64 bytes with identical re-encoding. Signing input MUST be ASCII `orbifabric.package.version-signature.v2` + LF + J(E with signature removed). Use RFC8032 Ed25519 (not Ed25519ph), signing subject_digest and signer/signed_at/key/official facts in the envelope to prevent replacement of attributed time/type. Implementations MUST reject noncanonical points/scalars, small-order public key/R and incorrect signatures; valid cryptography does not establish trusted identity. local_device omits official; orbifabric_official requires official, with Host trust based on environment/profile/key pins, not embedded self-claims. Core/Complete may be unsigned; Packtell formal exports follow PKG-SIGN-030/031 by default and formal Delivery requires at least one valid referenced signature. A selected signer MUST NOT silently fall back, and dual local+official signing is not required. Adding signatures does not change a Version.

## 13. Notes and tags / Notes 与 tags

`PKG-CONTRACT-013`: notes.v1 revisions MUST sort by (note_id,revision); note_id is UUIDv7, revisions start at 1 and are contiguous, and a note's target stays fixed across revisions. Current projection is the highest revision; deleted=true is a tombstone requiring an empty body; a later revision may explicitly restore it. tags.v1 revisions MUST form a global contiguous 1..n sequence; tags are nonempty NFC, case-sensitive text without leading/trailing whitespace; replay add/remove from the empty set for current projection, rejecting duplicate adds or removal of absent tags as INVALID_METADATA. metadata/package.json stores mutable current display facts, not sealed metadata. All portable document package_id values MUST agree; note targets reference objects present in history (event targets require corresponding events). Manifest reconstruction does not depend on note/event replay.

## 14. Events and provenance / Events 与 provenance

`PKG-CONTRACT-014`: events.ndjson MUST be zero bytes or one event.v1 JSON value per LF-terminated line, without empty lines/CR/BOM; file order is portable record order, not re-sorted by occurred_at. event_id is unique and schema_version=1; unknown optional namespaced types/data are preserved as uninterpreted facts; events requiring interpretation for correctness require a declared required capability. Known types are vocabulary observation labels and data is a JSON object of optional business explanation, not a state-transition program; version/notes/tags state remains defined by its documents. actor may be null; string IDs are privacy-safe opaque identities, not credentials. provenance.records MUST sort uniquely by provenance_id and be append-only; target is package/file/content; source_kind comes from the vocabulary; optional source_id/source_revision are non-secret opaque facts, not fetch URLs. A relationship references another Package and optionally its Version; reuse/copy/derived_from/supersedes never create a branch in this Package. Portable facts MUST NOT contain OAuth/refresh tokens, private keys, credentials/keyring references, signed URLs, absolute local paths, SQLite IDs, caches/indexes/embeddings/worker state. Schema validation is not redaction; Hosts select safe facts for export.

## 15. Delivery and evidence / Delivery 与 evidence

`PKG-CONTRACT-015`: delivery.v1 MUST cross-check package/version/subject_digest; signature_ids reference existing signatures for that Version, with at least one valid signature; a bad reference is not ignored because another is valid. DeliveryID/creation facts cannot be silently rewritten; new Deliveries get new IDs and one Version may have many Deliveries. evidence_refs is an append-only optional evidence inventory; embedded=true requires the file, false requires no network; later append does not change old subjects. delivery_digest is H(J(delivery with evidence_refs removed)), so appending evidence_refs does not change receipt-bound Delivery facts. evidence-envelope.v1 MUST select the matching `*-subject.v1` by kind and cross-check package/version/subject digest; receipts also check delivery_id/delivery_digest, and lifecycle witnesses check event_id/event_digest=H(J(event)). Envelope subject_digest=H(ASCII subject.schema + LF + J(subject)); signature input is ASCII `orbifabric.package.evidence-envelope.v1` + LF + J(envelope with signature removed). Key/Ed25519 validation follows the signature clause; each kind has a separate subject schema/key purpose; Host trust stores MUST bind key purpose to kind and cannot automatically treat a Version signer as an evidence issuer. Online revocation/status does not enter historical subjects; embedded snapshots do not represent current status. Evidence failures are independent of committed content integrity.

## 16. Portable filesystem / 可移植文件系统

`PKG-CONTRACT-016`: All path components MUST use Unicode 16.0.0 NFC and Default Full Case Folding (C/F mappings from CaseFolding.txt, not T); collision key=NFC(casefold(NFC(name))). Authority names must already be NFC; non-NFC is INVALID_PATH; materialization candidates first check NFC collisions (UNICODE_NORMALIZATION_CONFLICT), then case-fold collisions (CASE_CONFLICT), then individual invalid names. Paths MUST use relative `/` and reject absolute/drive/UNC paths, backslashes, empty components, `.`/`..`, NUL, C0/DEL, `<>:"|?*`, trailing dots/spaces and components over 255 UTF-16 code units. Reject case-insensitive Windows reserved basenames (before first dot, trailing spaces removed): CON/PRN/AUX/NUL/CONIN$/CONOUT$/COM1..9/LPT1..9 (including ¹²³ variants). Root display names do not enter logical identity. Portable trees MUST use only regular files/directories and reject symlinks/junctions/special files; hardlinks cannot be reconstruction dependencies and export writes independent bytes. Writers preflight the whole tree including control/extensions before publication, without silent collision renaming.

## 17. Directory and ZIP codecs / Directory 与 ZIP

`PKG-CONTRACT-017`: Directory export MUST stage outside the destination, validate the full plan/objects/history and publish with a no-overwrite commit; interruptions or non-atomic platforms require Host isolation of pending output, recovery or incomplete reporting, never false success. Version commit MUST protect expected HEAD, read a stable payload, write complete Version/objects and publish HEAD last; transaction intermediate states cannot be exposed as completed Packages. Host locks/journals stay outside the portable tree. ZIP v1 writers MUST use one top-level display directory; readers also accept an unwrapped root containing `.packtell/format.json` directly (the PKG-CODEC-020 SHOULD exception); multiple candidate roots or extra top-level siblings are rejected. UTF-8 ZIP names (UTF-8 flag for non-ASCII), STORE/DEFLATE and Zip64 MUST be supported; encryption, multi-volume and other methods are unsupported/unsafe; extra Unicode-name overrides are not trusted, paths use the UTF-8 entry name only. Implementations MUST check all central entries/implicit parents for duplicate, file/directory, NFC/case collision, traversal and mode before any output; local/central name/method/flags/size disagreement is rejected except legitimate deferred sizes using data descriptors; CRC and actual expanded size are verified. Explicit empty directories are preserved; entry order, compression level, mtime and permissions do not change logical subjects. ZIP artifact and Version digests remain separate.

## 18. Completeness proof and results / 完整性证明与结果

`PKG-CONTRACT-018`: Verifiers MUST separately report recognition, structure, working_state, committed_integrity, history_completeness, signature, identity, evidence and online. FULL algorithm: valid recognition/structure/schema/path/capability; one linear HEAD chain covering every Version; valid manifests/trees/references; enumerate all distinct ContentIDs and read each object path offline, verifying SHA-256/size (also check names/hashes of extra objects); required Complete portable files exist with valid revisions/references; declared embedded evidence exists. Only then report FULL, never from the label alone. Missing/unreadable objects or required Complete memory files give NOT_FULL; missing parents/nonlinear topology, schema/path/hash mismatch or invalid memory give INVALID. Bad signatures separately give signature=INVALID without changing complete correct bytes to NOT_FULL; invalid evidence is likewise separate, but missing declared embedded files gives NOT_FULL. No signatures means ABSENT, not missing history. Unperformed dimensions are NOT_CHECKED, never PASS. An UNBORN empty history can be FULL. Implementations MUST NOT substitute Working Tree bytes for a missing HEAD object or hydrate over the network and claim the original input was FULL. Offline proof covers the supplied Package committed chain, not the absence of malicious whole-history rollback/removal outside that input; freshness belongs to Host/evidence.

## 19. Capabilities and resource limits / 能力与资源限制

`PKG-CONTRACT-019`: vocabularies/core.v2.json MUST define the initial vocabulary and profiles/complete.v1.json is the Complete machine contract. Core understands linear-history/content-sha256; portable-memory requires notes/tags/provenance/events semantics; version-signature and delivery-evidence are independent. A required capability requires semantic understanding, not presence of every optional file. Export/import MUST preserve unknown optional extension bytes and allowed optional JSON fields; inability to preserve requires rejecting a lossy write or explicit user intent to remove them. Parsers MUST enforce entry count, single/total bytes, JSON depth/size, NDJSON line and compression-ratio limits before allocation/expansion; numerical limits are Host policy and produce RESOURCE_LIMIT rather than protocol corruption; conformance runners state their policy. SDKs do not obtain Provider credentials or automatically access networks; Resolver bytes are rehashed before output commit.

## 20. Shared field and result rules / 公共字段与结果规则

`PKG-CONTRACT-020`: All schema UUID fields MUST use lowercase RFC 9562 UUIDv7 (version 7, variant 8/9/a/b), never derived from ordinal/path/content; generation prevents collisions with IDs already used in this Package, and timestamp order does not replace parent authority. Times MUST use Gregorian years 0001..9999, valid dates, UTC `YYYY-MM-DDTHH:mm:ss.ffffffZ`, seconds 00..59, with no leap seconds, offsets or variable precision. Stop committing at the maximum ordinal, never wrap. format and version MUST declare required linear-history/content-sha256; Complete also requires portable-memory. Capability names use full vocabulary namespaces. When signatures/evidence occur, their corresponding capabilities must be declared required or optional; readers without optional semantics preserve bytes and report NOT_CHECKED, never claim verification. Provenance targets must exist in this Package history; event subjects may reference subsequently deleted historical entities but not nonexistent entities; package targets must equal this PackageID. IDs in control paths must match the respective IDs in their files. evidence_refs retain append order with unique evidence_id; signature_ids sort by UUID. Existing receipt/evidence subjects are immutable. Evidence kind and subject schema MUST map by replacing underscores with hyphens; all four kinds use evidence-envelope.v1, not Cloud API schemas.

`PKG-CONTRACT-021`: Result values in the vocabulary MUST be used by dimension. committed_integrity=VALID means all objects referenced by committed manifests pass hash/size; missing objects give UNAVAILABLE, wrong bytes INVALID, and unperformed checks NOT_CHECKED. Structure does not treat missing objects as invalid directory topology. Signature/evidence aggregation: no objects means ABSENT; all valid means VALID; any invalid means INVALID; unperformed means NOT_CHECKED; per-item results should remain available without hiding failures. Mathematically valid signatures without a trust pin give identity=UNTRUSTED, no signer gives UNKNOWN; only a matching Host-authorized trust rule gives TRUSTED. Online defaults to NOT_REQUESTED. With multiple errors, implementations MUST block unsafe paths/unsupported capabilities first, then check schema/topology, then content/signature/evidence; collecting more errors cannot justify unsafe reads. reason_codes is a deduplicated set, and tests require at least the expected code. Resource limits cannot masquerade as semantic PASS.

`PKG-CONTRACT-022`: Exact canonical string escape output bytes MUST be: quote→hex `5c22`, backslash→`5c5c`, BS→`5c62`, TAB→`5c74`, LF→`5c6e`, FF→`5c66`, CR→`5c72`; other C0 uses ASCII `\u00xx` (lowercase hex). These hex definitions remove prose-formatting escape ambiguity. Ed25519 verification MUST decode canonical curve points A and R, reject small-order points ([8]P equals identity), require 0≤S<L, and check the uncofactored equation `[S]B = R + [k]A`, with k=SHA-512(R_bytes || A_bytes || message) mod L and parameters from RFC8032; a permissive verifier checking only the cofactored equation and accepting more inputs is insufficient.
